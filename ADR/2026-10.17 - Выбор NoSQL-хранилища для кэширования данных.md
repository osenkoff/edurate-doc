
**ADR: 2026-10.15 - Выбор NoSQL-хранилища для кэширования данных**

**Дата:** 21 октября 2026 г.

**Статус:** Принято

**Контекст:**

В приложении EduRate необходимо предусмотреть механизм кэширования данных для снижения нагрузки на основную базу данных PostgreSQL и сокращения времени обработки повторяющихся запросов.

В кэше могут храниться часто запрашиваемые сведения об образовательных организациях, курсах и преподавателях, результаты поисковых запросов, данные для формирования рейтингов и другие временные сведения.

Использование кэширования позволит уменьшить количество повторных обращений к основной базе данных и повысить отзывчивость приложения при увеличении количества пользователей.

Необходимо выбрать NoSQL-хранилище, которое обеспечит быстрый доступ к данным, поддержку автоматического удаления устаревших записей и возможность интеграции с Django.

При выборе решения важно учитывать предполагаемую небольшую нагрузку на начальном этапе развития EduRate, простоту настройки и возможность дальнейшего масштабирования.

**Рассмотренные варианты:**

1. **Redis:** NoSQL-хранилище типа «ключ — значение», преимущественно работающее с данными в оперативной памяти. Поддерживает различные структуры данных, установку времени жизни записей (TTL) и использование в качестве кэша.
2. **Memcached:** распределённая система кэширования, работающая с данными в формате «ключ — значение». Предназначена для хранения временных данных в оперативной памяти и быстрого доступа к ним.
3. **MongoDB:** документоориентированная NoSQL-система управления базами данных. Позволяет хранить данные в формате BSON, выполнять запросы по полям документов и автоматически удалять устаревшие записи с помощью TTL-индексов

**Решение:**

Выбран Redis.

**Обоснование:**
- **Высокая скорость доступа:** хранение данных преимущественно в оперативной памяти обеспечивает быстрое получение часто используемой информации.
- **Поддержка TTL:** позволяет автоматически удалять устаревшие записи через заданный промежуток времени без необходимости самостоятельно выполнять очистку кэша.
- **Простота интеграции:** Redis поддерживается Django и может использоваться через готовые библиотеки и механизмы кэширования.
- **Соответствие назначению:** структура «ключ — значение» подходит для хранения результатов запросов, временных данных и часто используемой информации.
- **Поддержка различных структур данных:** Redis позволяет работать не только со строковыми значениями, но и со списками, множествами, хешами и другими структурами.
- **Снижение нагрузки на PostgreSQL:** повторные запросы могут обслуживаться из кэша без обращения к основной базе данных.
- **Возможность дальнейшего развития:** Redis может использоваться для дополнительных технических задач, например для хранения временных данных и работы с очередями.

**Последствия:**

- Необходимо развернуть Redis и настроить подключение к нему из серверной части Django.
- Следует использовать Redis для хранения результатов часто выполняемых запросов, данных каталога и других временных сведений. 
- Основные данные об образовательных организациях, курсах, преподавателях, пользователях и отзывах должны продолжать храниться в PostgreSQL.
- Для кэшируемых записей необходимо устанавливать время жизни (TTL), чтобы ограничивать срок хранения устаревшей информации.
- При изменении основных данных в PostgreSQL необходимо предусмотреть обновление или удаление соответствующих записей кэша.
- Следует предусмотреть возможность повторного получения данных из PostgreSQL при отсутствии записи в Redis.
- Необходимо ограничить объём используемой оперативной памяти и настроить политику удаления устаревших или редко используемых записей.
- Доступ к Redis должен осуществляться только со стороны серверной инфраструктуры с использованием механизмов аутентификации и сетевых ограничений.
- Нельзя использовать Redis как единственное место хранения критически важных данных, потеря которых приведёт к нарушению работы EduRate.
- Следует контролировать доступность Redis, объём используемой памяти и количество операций чтения и записи с помощью системы мониторинга.
