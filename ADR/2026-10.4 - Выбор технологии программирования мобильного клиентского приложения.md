
**ADR: 2026-10.4 - Выбор технологии программирования мобильного клиентского приложения**

**Дата:** 21 октября 2026 г.

**Статус:** Принято

**Контекст:** 

Для разработки мобильного приложения платформы EduRate необходимо выбрать технологию, которая обеспечит удобный пользовательский интерфейс, высокую производительность, кроссплатформенность и возможность эффективного развития продукта.

Предполагается выпуск приложения для Android и iOS. Поэтому предпочтительно использовать технологию, позволяющую разрабатывать обе версии приложения на основе единой кодовой базы, сокращая затраты на разработку, тестирование и сопровождение.

**Рассмотренные варианты:**

1. **React Native:** кроссплатформальный фреймворк для разработки мобильных приложений с использованием JavaScript или TypeScript и React. Позволяет переиспользовать значительную часть кода между Android и iOS.
2. **Flutter:** кроссплатформенный SDK от Google для разработки мобильных приложений с использованием единой кодовой базы. Позволяет создавать интерфейсы средствами Flutter и компилировать приложения для целевых платформ.
3. **Kotlin:** создание приложения для Android с использованием языка Kotlin и инструментов Android SDK. Обеспечивает прямой доступ к платформенным API, но для выпуска отдельного приложения на iOS потребуется другая технология.
4. **Swift:** создание приложения для устройств Apple с использованием Swift и инструментов Apple. Позволяет использовать возможности iOS напрямую, но для Android потребуется отдельная реализация.

**Решение:**

Выбран Flutter.

**Обоснование:**

- **Кросплатформенность:** Большую часть интерфейса и прикладной логики можно реализовать один раз для платформ Android и iOS.
- **Скорость разработки:** Готовые виджеты и возможность создавать переиспользуемые компоненты упрощают разработку экранов.
- **Гибкость интерфейса:** Собственная система виджетов позволяет создавать согласованный дизайн приложения и адаптировать его под особенности Android и iOS.
- **Hot Reload:** Позволяет быстро применять изменения в исходном коде и видеть результат в интерфейсе бзе полного преезапуска приложения, что упрощает проверку вариантов оформления экранов.
- **Снижение затрат на сопровождение:** Общая реализация для Android и iOS упрощает синхронизацию функциональности и выпуск обновлений.

**Недостатки:**

- **Различие платформ:** Кроссплатформенность не гарантирует полной идентичности поведения приложения на всех устройствах. Необходимо отдельно тестировать интерфейс, разрешения и платформенные функции.
- **Flutter Web:** Имеет особенности по сравнению с мобильной версией. Перед его выпуском необходимо проверить адаптивность интерфейса, навигацию, загрузку файлов, производительность и работу в браузерах.
- **Производительность:** Использование Flutter не гарантирует высокой производительности без дополнительной оптимизации. Необходимо контроллировать объём загружаемых данных, время выполнения операций и плавность интерфейса.
- **Размер приложения:** Приложение Flutter может занимать больше места, чем простое нативное приложение, из-за включения компонентов фреймворка и среды выполнения.

**Последствия:**

- Клиентское приложение разрабатывается на языке Dart с использованием Flutter.
- Интерфейс строится из переиспользуемых компонентов.
- Работа с серверными данными отделяется от представления и пользовательского интерфейса.
- Перед выпуском выполняется тестирование на поддерживаемых версиях Android, начиная с Android 10.0.
- При расширении на iOS и Web проводятся дополнительные проверки совместимости и удобства использования.
- Новые технологии для клиентской части не вводятся без обоснованной необходимости и отдельного архитектурного решения.
