
**ADR: 2026-10.3 — Выбор веб-фреймворка серверной части**

**Дата:** 21 октября 2026 г.

**Статус:** Принято

**Контекст:**

Для разработки серверной части EduRate необходимо выбрать фреймворк, который обеспечит создание API для мобильного приложения, управление данными, аутентификацию пользователей, модерацию отзывов и взаимодействие с административной частью системы.

Платформа должна поддерживать работу с образовательными организациями, программами, преподавателями, рейтингами и отзывами, а также предоставлять механизмы защиты персональных данных и контроля доступа в зависимости от роли пользователя.

При выборе фреймворка необходимо учитывать скорость разработки, наличие готовых компонентов, удобство тестирования, безопасность и возможность масштабирования.

**Рассмотренные варианты:**

1. **Django:** полнофункциональный веб-фреймворк Python со встроенной ORM, системой аутентификации, миграциями базы данных и административной панелью. Подходит для приложений с развитой бизнес-логикой и управлением данными.
2. **FastAPI:** веб-фреймворк Python, ориентированный на создание API, с поддержкой асинхронных обработчиков, аннотаций типов и автоматической генерации документации OpenAPI.
3. **Flask:** минималистичный веб-фреймворк Python, предоставляющий базовые средства разработки веб-приложений. Дополнительные компоненты для аутентификации, работы с данными и административного управления выбираются отдельно.

**Решение:**

Выбран Django

Для создания API мобильного приложения планируется использовать Django REST Framework.

**Обоснование:**

- **Быстрая разработка:** Django предоставляет готовые механизмы маршрутизации, обработки запросов, работы с базой данных и миграций.
- **Административная панель:** Встроенный инструмент Django Admin позволит реализовать управление образовательными организациями, программами, преподавателями и пользовательским контентом с минимальными первоначальными затратами.
- **Аутентификация и права доступа:** Встроенные механизмы Django упрощают реализацию регистрации, управления пользователями и разграничения прав доступа.
- **Работа с данными:** ORM позволяет описывать модели предметной области и взаимодействовать с реляционной базой данных без необходимости вручную писать большинство SQL-запросов.
- **Безопасность:** Фреймворк предоставляет встроенные механизмы защиты от распространённых веб-уязвимостей при условии корректной настройки и использования.
- **Сопровождение:** Развитая экосистема и единые соглашения фреймворка упрощают поддержку и развитие проекта.
- **Поддержка API:** Django REST Framework предоставляет средства сериализации, валидации входных данных, пагинации, аутентификации и управления доступом.
- **Горизонтальное масштабирование:** Приложение можно запускать в нескольких экземплярах за балансировщиком нагрузки, отделяя обработку HTTP-запросов от фоновых задач.

**Недостатки**

- **Избыточность для небольших API:** Django предоставляет больше встроенных возможностей, чем может потребоваться простому сервису.
- **Необходимость освоения экосистемы:** команде потребуется изучить архитектуру Django и Django REST Framework.
- **Особенности асинхронной обработки:** не все используемые компоненты и операции одинаково хорошо подходят для асинхронного выполнения, поэтому фоновые задачи следует организовывать отдельно.
- **Необходимость настройки производительности:** ORM-запросы, сериализация и обработка больших списков требуют оптимизации по мере роста нагрузки.

**Последствия:**

- Необходимо организовать серверную часть как модульный монолит с логически разделёнными приложениями Django.
- Следует использовать Django REST Framework для реализации API мобильного приложения.
- Следует использовать Django Admin для административного управления каталогом и контентом, ограничив доступ по ролям.
- Необходимо реализовать отдельные механизмы модерации отзывов и подтверждения факта обучения.
- Необходимо использовать автоматизированные тесты, миграции базы данных и механизмы проверки прав доступа.
- Для горизонтального масштабирования следует исключить зависимость критически важного состояния от памяти отдельного экземпляра приложения.
- Следует настроить безопасное хранение секретов, журналирование, мониторинг и резервное копирование.
