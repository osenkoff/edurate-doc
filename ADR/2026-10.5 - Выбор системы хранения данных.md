
**ADR: 2026-10.5 - Выбор системы хранения данных**

**Дата:** 21 октября 2026 г.

**Статус:** Принято

**Контекст:**

Для приложения EduRate необходимо выбрать систему хранения данных. В базе будут храниться сведения об образовательных организациях, курсах, преподавателях, пользователях, отзывах, оценках и избранном.

Важно обеспечить целостность данных, возможность поиска и фильтрации организаций, сохранность отзывов и удобство дальнейшего развития приложения.

**Рассмотренные варианты:**

1. **PostgreSQL:** Объектно-реляционная система управления базами данных.
2. **MySQL:** Популярная реляционная система управления базами данных.
3. **MongoDB:** Документоориентированная система управления базами данных.
4. **SQLite:** Реляционная база данных, подходящая для локального хранения данных на устройстве

**Решение:**

Выбран PostgreSQL.

**Обоснование:**

- **Надежность:** поддержка транзакций и механизмов восстановления помогает защищать данные от потери и несогласованных изменений.
- **Расширяемость:** структуру базы можно развивать по мере появления новых функций приложения.
- **Оптимизация запросов:** Отличный планировщик запросов, который оптимизирует сложные запросы.
- **JSON поддержка:** Встроенная поддержка JSON позволяет работать с неструктурированными данными.
- **Поиск и фильтрация:** PostgreSQL позволяет выполнять запросы для поиска организаций и курсов по различным параметрам.

**Ограничения:**

- **Сложные запросы:** при росте объёма данных может потребоваться оптимизация.
- **Резервное копирование:** необходимо регулярно создавать и проверять резервные копии.
- **Защита данных:** требуется настроить права доступа и безопасное подключение.
- **Изменение структуры:** обновление схемы базы требует миграций и проверки совместимости.
  
**Последствия:**

- Основные данные EduRate хранятся в PostgreSQL на серверной стороне.
- Связи между организациями, курсами, преподавателями, пользователями и отзывами отражаются в структуре базы данных.
- Доступ к базе осуществляется через серверную часть приложения, а не напрямую из мобильного клиента.
- Для изменения структуры базы используются миграции.
- Необходимо настроить резервное копирование, управление доступом и контроль целостности данных.
- Локальное хранение данных на устройстве, если оно потребуется, рассматривается отдельно от основной серверной базы данных.
