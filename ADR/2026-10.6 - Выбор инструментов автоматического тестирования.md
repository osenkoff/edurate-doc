
**ADR: 2026-10.6 — Выбор инструментов автоматического тестирования**

**Дата:** 21 октября 2026 г.

**Статус:** Принято

**Контекст:**

Для обеспечения качества EduRate необходимо выбрать инструменты автоматического тестирования мобильного приложения, серверного API, веб-интерфейсов (при необходимости), а также инструменты модульного и нагрузочного тестирования. Выбор должен соответствовать технологическому стеку проекта: Flutter, Python, Django REST Framework и PostgreSQL.

**Рассмотренные варианты:**

- **Веб-интерфейсы:** Playwright, Selenium, Cypress.
- **Мобильное приложение:** Flutter Test, Flutter integration_test, Appium.
- **API:** Django REST Framework APIClient, Postman, Newman, Schemathesis.
- **Нагрузочное тестирование:** Locust, JMeter, k6.
- **Модульное тестирование:** pytest, unittest, Flutter Test.

**Решение:**

Для автоматического тестирования EduRate выбраны следующие инструменты:

- Playwright — для автоматизации тестирования веб-интерфейсов, если они будут использоваться в проекте.
- Flutter Test и Flutter integration_test — для модульного тестирования, проверки виджетов и интеграционных сценариев мобильного приложения.
- Django REST Framework APIClient — для автоматизированной проверки серверного API.
- Locust — для нагрузочного тестирования серверной части и оценки её поведения при увеличении числа пользователей.
- pytest — для модульного и интеграционного тестирования серверной бизнес-логики.
- GitHub Actions — для автоматического запуска тестов и проверок при изменении кода.

**Обоснование:**

Выбранные инструменты совместимы с технологическим стеком EduRate, покрывают основные уровни тестирования и позволяют автоматизировать проверки без избыточного усложнения инфраструктуры. pytest и APIClient подходят для тестирования серверной части на Python, инструменты Flutter — для мобильного приложения, а Locust позволяет моделировать нагрузку на API. Playwright предусмотрен для веб-интерфейсов при возникновении такой необходимости.

**Последствия:**

- Для серверной части будут созданы автоматизированные тесты бизнес-логики, API, авторизации и прав доступа.
- Для мобильного приложения будут реализованы тесты виджетов и ключевых пользовательских сценариев.
- Нагрузочные испытания будут проводиться отдельно от обычных модульных тестов.
- GitHub Actions будет использоваться для запуска автоматических проверок в процессе разработки.
- Веб-тестирование с Playwright будет внедрено при появлении соответствующего веб-интерфейса.
- При необходимости расширения тестирования допускается подключение дополнительных инструментов без изменения основного набора.
