
**ADR: 2026-10.10 - Обеспечение работоспособности основного функционала**

**Дата:** 21 октября 2026 г.

**Статус:** Принято

**Контекст:**

Основные сценарии EduRate включают регистрацию и авторизацию, поиск учебных заведений и преподавателй, просмотр информации и отзывов, работу с избранным и отправку отзывов на модерацию.

Ошибки в этих сценариях могут сделать приложение практически бесполезным для пользователей. Необходимо снизить риск регрессий и обеспечить возможность своевременно обнаруживать и устранять неисправности.

**Рассмотренные варианты:**

1. **Проверка только перед выпуском:** основные функции тестируются вручную после завершения разработки. 
2. **Автоматическое тестирование:** критические сценарии проверяются автоматизированными тестами при изменении кода. 
3. **Комплексный контроль качества:** автоматические тесты дополняются проверкой кода, интеграционными тестами, мониторингом и проверкой перед выпуском.

**Решение:**

Выбран комплексный контроль качества.

**Обоснование:**

- **Разделение ответственности:** функциональность распределяется по модулям каталога, пользователей, отзывов, рейтингов, модерации и уведомлений. 
- **Изоляция изменений:** модули взаимодействуют через определённые интерфейсы, что снижает вероятность непреднамеренного влияния изменений на другие части системы.
- **Автоматическое тестирование:** серверные тесты выполняются с помощью pytest и Django REST Framework APIClient, мобильные — с помощью Flutter Test и integration_test. 
- **Проверка изменений:** автоматические проверки запускаются через CI при внесении изменений в код.
- **Контроль ошибок:** Sentry используется для регистрации ошибок мобильного приложения и серверной части, а Prometheus и Grafana — для мониторинга состояния серверов и API.

**Последствия:**

- Для критических пользовательских сценариев необходимо создать модульные, интеграционные и API-тесты. 
- Перед объединением изменений выполняются предусмотренные автоматические проверки и Code Review. 
- Перед выпуском проверяются основные сценарии регистрации, поиска, просмотра отзывов, избранного и модерации. 
- Необходимо контролировать время ответа API и ошибки выполнения запросов. 
- При обнаружении критической ошибки следует приостанавливать выпуск затронутой функциональности до её исправления. 
- Изменения схемы базы данных должны сопровождаться миграциями и проверками совместимости.
