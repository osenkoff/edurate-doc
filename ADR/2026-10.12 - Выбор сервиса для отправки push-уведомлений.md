
**ADR: 2026-10.11 - Выбор сервиса для отправки push-уведомлений**

**Дата:** 21 октября 2026 г.

**Статус:** Принято

**Контекст:**

В приложении EduRate необходимо реализовать механизм отправки push-уведомлений пользователям. Уведомления должны информировать о важных событиях, связанных с использованием приложения, например, об изменении статуса отзыва после проверки модератором.

Необходимо выбрать сервис, который позволит серверной части отправлять уведомления на мобильные устройства, обеспечит интеграцию с Flutter-приложением и будет учитывать требования к обработке персональных данных.

При выборе решения важно учитывать доступность сервиса для российских пользователей, простоту интеграции, надёжность доставки уведомлений и возможность дальнейшего развития системы.

**Рассмотренные варианты:**

1. **Firebase Cloud Messaging (FCM):** сервис Google для отправки push-уведомлений на мобильные устройства. Поддерживает интеграцию с Android и другими платформами, предоставляет API для отправки уведомлений.
2. **RuStore Push Notifications:** сервис отправки push-уведомлений от RuStore. Предоставляет SDK и REST API для взаимодействия с серверной частью приложения.
3. **Huawei Push Kit (HMS):** сервис Huawei для отправки уведомлений на устройства с поддержкой мобильных сервисов Huawei.

**Решение:**

Выбран RuStore Push Notifications.

**Обоснование:**

- **Доступность для российской аудитории:** сервис ориентирован на использование в российской экосистеме мобильных приложений.
- **Интеграция с серверной частью:** RuStore предоставляет REST API, позволяющий отправлять уведомления непосредственно из серверной части EduRate.
- **Интеграция с Flutter:** сервис можно использовать в мобильном приложении для получения push-токенов и обработки поступающих уведомлений.
- **Отсутствие необходимости разрабатывать собственную инфраструктуру:** доставка уведомлений обеспечивается внешним сервисом.
- **Возможность расширения:** в дальнейшем можно рассмотреть использование универсального API RuStore для работы с несколькими push-провайдерами.

**Последствия:**

- Необходимо интегрировать SDK RuStore Push Notifications в мобильное приложение EduRate.
- Серверная часть должна обеспечивать отправку уведомлений через REST API RuStore.
- Необходимо реализовать получение push-токена на мобильном устройстве и передачу его серверной части.
- Push-токены должны храниться на серверной стороне с ограничением доступа и связываться с соответствующими пользовательскими устройствами.
- Следует предусмотреть обновление и удаление недействительных push-токенов.
- В уведомлениях необходимо передавать только минимально необходимую информацию. Не следует включать персональные данные пользователей и содержимое подтверждающих документов.
- Необходимо предусмотреть обработку ошибок отправки и возможность повторной отправки уведомлений.
- До начала эксплуатации требуется проверить условия обработки данных, размещение инфраструктуры и договорные обязательства провайдера на соответствие требованиям ФЗ-152.
- При невозможности использования выбранного сервиса следует повторно рассмотреть альтернативные push-провайдеры.
